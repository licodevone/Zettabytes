**Verificações (resumo):** Windows com PowerShell 7.6.10; Python global 3.13.15; uv 0.12.17 instalado. Backend em `apps/api`, com `pyproject.toml`, `uv.lock` e `.python-version` definido como 3.12. Ambiente existente em `apps/api/.venv` executa Python 3.12.14 e importa FastAPI 0.141.1. Política de execução do PowerShell em RemoteSigned. Consultada documentação oficial do uv via Context7. Nenhuma dependência instalada e nenhum ambiente recriado durante a verificação.

**Resposta final:**

Verifiquei o projeto: o backend Python fica em `apps/api`, utiliza **uv** e define **Python 3.12**. O `uv` já está instalado e **já existe um ambiente virtual funcional** em `apps/api/.venv`, com Python 3.12.14.

Siga este passo a passo no **PowerShell**:

1. Entre na pasta do backend:

   ```powershell
   cd D:\projects\my-project\acmebr-projects\atendimentos.acmebr\apps\api
   ```

2. Crie ou sincronize o ambiente e instale as dependências nas versões do projeto:

   ```powershell
   uv sync --locked
   ```

   Esse comando cria a pasta `.venv` se ela não existir. Como ela já existe neste computador, sincroniza o ambiente existente. Não é necessário executar `python -m venv` separadamente. [Documentação do uv](https://docs.astral.sh/uv/guides/projects/).

3. Ative o ambiente:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

4. Confirme que está usando o Python do ambiente:

   ```powershell
   python --version
   python -c "import sys; print(sys.executable)"
   ```

   O executável deve apontar para `apps\api\.venv\Scripts\python.exe`. No ambiente atual, a versão é `Python 3.12.14`.

5. Para sair do ambiente:

   ```powershell
   deactivate
   ```

**Para usar o ambiente que já está pronto agora, basta executar os passos 1 e 3.** A política atual do PowerShell já permite scripts locais; não é necessário alterá-la.
